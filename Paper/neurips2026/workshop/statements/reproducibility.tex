\section{Reproducibility statement}
\label{sec:stmt:reproducibility}

This section states what a reader would need in order to reproduce the numbers
in this paper, and what we did to make the numbers reproducible for ourselves.

\paragraph{One protocol, declared in one place.}
Every hyperparameter of the matched sweep is declared as data in a single
module of the codebase (\texttt{project/test\_notebooks/nb\_common.py}), which
holds one base configuration per model family and one override block per phase:
dense pre-training, the iterative-pruning baseline, and the contrastive arm.
No hyperparameter is typed per experiment, so the two arms cannot drift apart
by accident: they read the same schedule, the same pruning criterion, the same
epoch budget, the same fine-tuning stage and the same clipping and precision
settings, and they differ only in the training objective. That module is the
authoritative statement of the protocol, and the appendix tables are
transcriptions of it.

\paragraph{Data and splits.}
CIFAR-10 obtained through the standard \texttt{torchvision} loader, partitioned
9:1 into 45{,}000 training and 5{,}000 validation images, with the 10{,}000-image
test set held out and used only for the final report. The split is drawn under
its own recorded seed, which is stored in every run record, so the same
partition is reconstructible independently of the training seed. Evaluation is
sample-weighted over all 10{,}000 test images: an earlier defect that silently
dropped the final partial batch, and so scored only 9{,}728 of them, was fixed,
and any record produced with a non-zero dropped-sample count is refused by the
results generator rather than averaged in.

\paragraph{Seeds.}
Runs are seeded explicitly and the seed is recorded with its provenance,
distinguishing a seed passed to the run from one inherited from the global
state. Headline cells are planned at three seeds; the objective ablation is
single-seed. Every figure in the paper carries its own seed count, so a
single-seed number is visible as one. Aggregates across seeds are the mean and
the sample standard deviation with $ddof = 1$.

\paragraph{Hardware and numerics.}
A single NVIDIA A100 on a 24-vCPU cloud node, with runs serialised so that one
training job owns the GPU. Training uses bf16 autocast with gradient clipping at
global norm 10.0 on both arms. Each run record captures the torch, CUDA and
cuDNN versions, the GPU name and count, and the determinism flags in force.
We do not claim bitwise determinism: the runs are not executed under
deterministic kernels, and the appropriate reference for run-to-run variation is
the measured noise floor reported with the results rather than an expectation of
exact reproduction.

\paragraph{Run records are append-only and idempotent.}
Each phase of each run writes one JSON record, named from a run identifier and
the phase. If a record of that name already exists the writer does not overwrite
it; it appends a numeric suffix and writes a new file. A re-run therefore adds
evidence and never destroys it, and the record set is an audit trail rather than
a cache. Alongside each record the writer stores the git commit and, when the
working tree was dirty, a patch of the uncommitted difference, so a record can
be tied to the exact code that produced it. The record also carries the
configuration, the environment capture, the status, and the dropped-sample
count that gates its admissibility.

\paragraph{No number in this paper was typed by hand.}
Every accuracy, delta and error bar in the prose, in the tables and in the
abstract is a macro call. Those macros are generated by a script that reads the
run records, selects one record per cell and seed by phase priority, discards
records that are marked as smoke tests, that did not complete successfully, or
that dropped evaluation samples, and aggregates the survivors into a mean, a
sample standard deviation and a seed count. Deltas between the two arms are
computed for every cell where both arms landed, rather than being subtracted by
hand. A cell that has not been measured has no macro, and renders in the
compiled document as a conspicuous placeholder together with a warning in the
build log, so an unfinished cell cannot be shipped as a number. Regenerating the
macro file from the record set is a single command, and the file is not edited
by hand.

\paragraph{Code availability.}
The code is not linked from this submission, because the repository is not
anonymous and a link would identify the authors during double-blind review. It
will be released publicly under a permissive open-source licence upon
acceptance, and can be made available to reviewers during the discussion period
through an anonymized mirror on request. The protocol above, together with the
appendix, is intended to be sufficient to reimplement the experiments without
it.
